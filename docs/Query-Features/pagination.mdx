# Pagination

The API returns products in pages, so a large catalog is retrieved in smaller sets instead of one big response. By default, each page has **10 products**.

| Method | Endpoint | Purpose |
|---|---|---|
| <Method type="GET" /> | `/api/products` | Retrieve a list of catalog products |

:::tip[Try it live]

Open `GET /api/products` in [Swagger UI](https://vikram-swaggerui.onrender.com), enter values for `page` and `limit`, and select **Execute**.

:::

## Pagination Parameters

Both parameters are optional.

| Name | Type | Default | Description |
|---|---|---|---|
| `page` | integer | `1` | Which page of results to return |
| `limit` | integer | `10` | Maximum number of products per page |

## Example: 20 Products, 5 per Page

| Request | Returns |
|---|---|
| `?page=1&limit=5` | Products 1 to 5 |
| `?page=2&limit=5` | Products 6 to 10 |
| `?page=3&limit=5` | Products 11 to 15 |
| `?page=4&limit=5` | Products 16 to 20 |

## Read the Pagination Info

Every list response includes a `pagination` object, so you know where you are and how many pages are left:

```json
{
  "data": [ ... ],
  "pagination": {
    "page": 2,
    "limit": 5,
    "total": 20,
    "totalPages": 4
  }
}
```

| Field | Meaning |
|---|---|
| `page` | The page you requested |
| `limit` | The number of products per page |
| `total` | The total number of products that match your request |
| `totalPages` | The total number of pages. Stop requesting when `page` reaches this value |

## Combine Pagination

Pagination works together with filtering and sorting. The filters and sorting are applied first, and then the results are split into pages.

| Goal | Request |
|---|---|
| Page through a category | `GET /api/products?category=electronics&page=1&limit=5` |
| Second page of in-stock products | `GET /api/products?status=in_stock&page=2&limit=5` |
| Sorted and paged | `GET /api/products?sort=-price&page=1&limit=5` |
| All together | `GET /api/products?category=electronics&status=in_stock&sort=-price&page=1&limit=5` |
