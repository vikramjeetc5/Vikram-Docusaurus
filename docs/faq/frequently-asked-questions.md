# Frequently Asked Questions

This page answers common questions about the E-Commerce Product Catalog API.

## What is the E-Commerce Product Catalog API?

The E-Commerce Product Catalog API is a RESTful API for managing products in an e-commerce catalog.

It provides endpoints for:

- Creating products
- Retrieving products
- Updating products
- Deleting products
- Filtering products
- Sorting products
- Paginating product results

## What HTTP methods does the API support?

The API uses standard HTTP methods:

| Method | Purpose |
|---|---|
| `GET` | Retrieve products |
| `POST` | Create a product |
| `PUT` | Update a product |
| `DELETE` | Delete a product |

## How do I retrieve all products?

Send a `GET` request to:

GET /api/products


## How do I retrieve a specific product?

Include the product ID in the URL:

GET /api/products/1


Replace `1` with the ID of the product you want to retrieve.

## How do I create a product?

Send a `POST` request to:

POST /api/products


Include the product information as JSON in the request body.

Example:
```bash

{ "name": "Wireless Headphones", "category": "electronics", "price": 79.99, "status": "in_stock" }
```

## How do I update a product?

Send a `PUT` request with the product ID:

PUT /api/products/1


Include the updated product information in the request body.

## How do I delete a product?

Send a `DELETE` request with the product ID:

DELETE /api/products/1


## How do I filter products?

Use the `category` or `status` query parameters.

For example:

GET /api/products?category=electronics


Or:

GET /api/products?status=in_stock


## How do I sort products?

Use the `sort` query parameter.

Sort by price from lowest to highest:

GET /api/products?sort=price


Sort by price from highest to lowest:

GET /api/products?sort=-price


Sort alphabetically by name:

GET /api/products?sort=name


## How does pagination work?

Use the `page` and `limit` parameters.

For example:

GET /api/products?page=1&limit=5


This requests the first page with a maximum of five products.

The default page size is **10 products per response**.

## Can I combine filtering, sorting, and pagination?

Yes.

For example:

GET /api/products?category=electronics&status=in_stock&sort=-price&page=1&limit=5


This combines:

- Category filtering
- Status filtering
- Price sorting
- Pagination

## Where can I test the API?

The API can be tested using Swagger UI.

When running locally, open:

http://localhost:3000/api-docs


## What is Swagger UI used for?

Swagger UI provides an interactive interface for exploring and testing the API.

You can use it to:

- View endpoints
- View parameters
- Submit requests
- Inspect responses
- Test CRUD operations
- Test filtering, sorting, and pagination

## What does a 404 response mean?

A `404 Not Found` response usually means that the requested resource does not exist.

For example:

GET /api/products/9999


If product `9999` does not exist, the API may return:

404 Not Found


## What does a 400 response mean?

A `400 Bad Request` response generally indicates that the request contains invalid or incomplete data.

Check:

- Request parameters
- Request body
- Data types
- Required fields
- Supported values

## What product statuses are supported?

The API supports:

instock outof_stock discontinued


## Can I use Swagger UI instead of Postman?

Yes.

Swagger UI provides an interactive interface that allows you to send requests directly from your browser.

Postman or another API client can also be used if preferred.
